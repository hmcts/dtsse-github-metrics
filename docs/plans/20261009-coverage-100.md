# Plan: Lift test coverage to 100% as reported by SonarCloud

## Overview
Bring every source file under `src/` to 100% statements, branches, functions and lines in the merged unit and
integration coverage that SonarCloud reads. Remove the Sonar analysis and coverage exclusions that currently hide
files from the figure, so the 100% Sonar shows covers all of the code, not a subset.

## Context
- Baseline (2026-10-09): unit 96.35/92.14/97.79/96.48 (stmts/branches/fns/lines), 58 files below 100%;
  integration has 90 statements and 49 branches uncovered across 21 files.
- Coverage configs: `vitest.config.mts` (unit, `coverage/lcov.info`), `vitest.integration.config.mts`
  (Postgres, `coverage-integration/lcov.info`). Sonar merges both via `sonar-project.properties`.
- Sonar currently hides: `sonar.exclusions` drops `src/app/**`, `src/components/**`, `src/lib/**`,
  `src/instrumentation.ts`, `src/proxy.ts`; `sonar.coverage.exclusions` drops `behaviour/fill.ts`, `cli/run.ts`,
  `app/**`, `lib/api.ts`, `preview/main.ts`, `preview/processes.ts`. `cve/cosmos.ts` and `store/prisma.ts` are in
  neither lcov, so Sonar reads them as 0%.
- `error instanceof Error ? error.message : String(error)` appears 51 times across `src/` (cli, auth, platform,
  preview, and most of `evidence/**`); its `String(error)` arm is reachable only when a library throws a
  non-`Error`.
- Related patterns: unit tests sit beside the source as `*.test.ts`/`*.test.tsx` (React tests use the
  `@vitest-environment jsdom` docblock; `src/lib` keeps its tests in `src/lib/__tests__`); integration tests live in
  `test/integration/*.test.ts` and need Postgres (`yarn deps:up && yarn db:migrate:dev`). Shared non-UI helpers
  live in `src/platform/` with a sibling test.
- Dependencies: none new. Mock `@azure/cosmos`, `node:child_process` and Prisma with `vi.mock`, as existing tests
  do.

## Development Approach
- Code-then-tests: the code exists; add tests that reach each uncovered line and branch reported by
  `yarn test:coverage` / `yarn test:integration` (the `text` reporter lists uncovered lines per file).
- Test behaviour through public exports; do not export internals only to test them.
- Uncovered branches are handled by kind:
  - Truly dead code, where no input to the function can reach the branch (e.g. the `?? [identifier]` fallback in
    `policy/repositories.ts:67`, whose map is built from the same array it is looked up with): refactor it away.
  - Defensive checks a direct call can reach even if the loader or schema never passes such input (e.g. the
    duplicate-team guard in `policy/repositories.ts:36`): test them by calling the function directly with a
    hand-built argument.
  - The `instanceof Error ? … : String(error)` pattern: replaced everywhere by one tested helper,
    `messageOf(error: unknown): string`, in Task 1.
- Do NOT add `/* v8 ignore */` or `/* istanbul ignore */` comments, and do not replace a guard with a type cast.
- Partition ownership: each file is held at 100% by exactly one suite. The integration suite owns files that talk
  to Postgres; the unit suite owns everything else. Sonar's merged figure is then 100% by construction.
- Thresholds are raised to 100 in the final config task, so earlier tasks verify their files via the coverage
  report, not the gate.
- Complete each task fully before moving to the next.
